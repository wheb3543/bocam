# جرد التكامل النهائي لنظام الإشعارات الموحد

**النطاق:** تدفقات التشغيل ولوحة الإدارة في SGH CRM.
**تاريخ الجرد:** 25 أغسطس 2026.
**منهجية التحقق:** مراجعة نقاط التنفيذ، عقود سياسة الإشعارات، الجداول والمسارات الدورية، ثم اختبار سير الإشعارات وفحص الأنواع والبناء.

## الخلاصة التنفيذية

اكتمل ربط أحداث التشغيل ذات الأولوية بمركز الإشعارات الموحد. تمر التنبيهات الموجهة بالأدوار عبر `notifyEligibleRecipients`، بينما يستخدم الإسناد الفردي المسار الذي يتحقق من تفضيلات المستخدم وسياسة النظام قبل إنشاء الإشعار. لا تحمل الإشعارات الجديدة بيانات مرضى أو نتائج مختبر أو أسرار أو رموز وصول، كما أن مسارات الأعمال الأصلية لا تنتظر نجاح الإشعار.

| محور التغطية | الحالة | النتيجة العملية |
|---|---|---|
| مركز الإشعارات والتفضيلات | مكتمل | قراءة، تمييز الكل كمقروء، تصفية غير المقروء، تجميع حسب المصدر، تنبيه مرئي/صوتي، ملخص يومي قابل للإدارة وعند الطلب. |
| رسائل وصندوق التواصل | مكتمل | WhatsApp والصندوق الاجتماعي يبلغان عن الوارد والإسناد ضمن سياسة المستلم. |
| المهام والعملاء المحتملون | مكتمل | إشعارات الإسناد والاستحقاق والتأخر، وإنشاء العميل المحتمل وتغيير مرحلته. |
| التكاملات والحملات والمحتوى | مكتمل | انقطاع التفويض، تعيين المراجع أو قائد الحملة، ومؤشرات نهاية الحملة والميزانية. |
| المواعيد | مكتمل | تغيّر الجدولة وفشل الرسائل، مع تذكيرات 24 ساعة وساعة واحدة عبر مسار دوري محمي. |
| الوسائط وCMS | مكتمل | ملخص واحد لنتيجة رفع الدفعة أو استيراد/تصدير CMS، مع رابط مباشر إلى سجل عمليات المحتوى. |
| طلبات الوصول | مكتمل | تنبيه للمسؤول عند طلب جديد، وتنبيه داخل الحساب المعتمد عند القبول؛ مراجعة الطلبات محصورة بالخادم في دور المسؤول. |
| العمليات منخفضة الضجيج | مكتمل | فشل أولي ثم تعافٍ واحد للاستعادة والنسخ والترخيص ومزامنة القوالب وفحص التحديثات. |

> **قاعدة التشغيل المعتمدة:** لا يُنشأ إشعار لكل سطر سجل أو لكل محاولة متكررة. تسجل حالة العملية على أنها سليمة أو متدهورة؛ يرسل أول انتقال إلى الفشل، ثم إشعار واحد فقط عند عودة العملية إلى السليم.

## التدفقات المنفذة ومصادرها

| المجال | الأحداث المغطاة | المصدر في السياسة | آلية تقليل الضجيج أو منع التكرار |
|---|---|---|---|
| الحجوزات | إنشاء، تغيّر حالة، تغيّر التاريخ أو الطبيب، فشل رسالة الموعد، تذكير الموعد | `bookings` | تذكيرات WhatsApp محمية بسجل الإرسال؛ الوظيفة الدورية تعمل كل 30 دقيقة. |
| المهام | الإسناد، قرب الاستحقاق، التأخر | `tasks` | مواعيد التذكير تحفظ طوابع الإرسال وتعمل كل ساعة. |
| العملاء والتواصل | العملاء المحتملون، رسائل WhatsApp، الرسائل/التعليقات الاجتماعية، التعيينات | `leads` و`whatsapp` و`social_inbox` | الإشعار موجّه إلى المكلّف أو الأدوار المؤهلة حسب السياسة. |
| التكاملات والحملات | فشل الاتصال، اقتراب انتهاء التفويض، تعيين القائد، تاريخ النهاية والميزانية | `integrations` و`campaigns` | فحوص يومية وحالة إبلاغ محفوظة تمنع الإعادة. |
| CMS والوسائط | نتائج الرفع، الاستيراد، التصدير | `content` | ملخص لكل عملية/دفعة، مع تسجيل نتيجة العملية في سجل محتوى قابل للفلترة. |
| طلبات الوصول | تقديم الطلب، اعتماده، رفضه | `security` | لا تتضمن الرسائل البريد أو الاسم؛ إجراءات المراجعة محمية بدور المسؤول. |
| العمليات | فشل أو تعافي النسخ/الاستعادة، الترخيص، مزامنة القوالب، فحص التحديث | `operations` | جدول `operationalAlertStates` يحفظ انتقال الحالة ويمنع تكرار الفشل المتواصل. |

## الفجوات والحدود الفعلية المتبقية

لا توجد بنود ربط عالية أو متوسطة الأولوية متبقية في قائمة العمل الحالية. توجد حدود مقصودة ينبغي مراعاتها عند أي توسع لاحق:

| الموضوع | الوضع الحالي | قرار المتابعة المقترح |
|---|---|---|
| قرار رفض طلب الوصول | لا يملك صاحب الطلب المرفوض حساباً نشطاً، لذلك لا يمكن وضع إشعار صندوق وارد له بلا إنشاء هوية غير مصرح بها. تظهر حالة الرفض عند إعادة محاولة الدخول، ويصل تنبيه تشغيلي لمالك المشروع. | عند اعتماد قناة بريد أو رسالة رسمية، يضاف موصل خارجي مستقل مع موافقة على المحتوى وسياسة الاحتفاظ. |
| مزامنة منصات إضافية | التجميع الحالي يغطي مزامنة قوالب WhatsApp الشاملة. | توسع أي موصل مزامنة جديد عبر `recordOperationalResult`، لا عبر تنبيهات مباشرة في كل `catch`. |
| فحص التشغيل الحي | تم التحقق من المسارات والحماية والبناء؛ لا تُفبرك حالات فشل أو رسائل إنتاجية لاختبار الجرس. | راقب سجل مهام Heartbeat بعد أول تشغيل طبيعي للتحقق من الاستجابة التشغيلية. |

## ضوابط الاستمرار

ينبغي أن يبقى أي ربط جديد fire-and-forget، وأن يحترم `sourceEnabled` وتفضيلات المستلم والأدوار النظامية. تستخدم الأعمال الدورية مسارات `/api/scheduled/*` المحمية بمصادقة المهمة ومعرّف محفوظ في قاعدة البيانات؛ لا تستخدم `setInterval` أو `node-cron` للجدولة داخل عملية الخادم.
