# مرجع تشغيل الترخيص وحماية التشغيل

**الحالة:** `working`
**الجمهور:** المطورون والمشغلون وفريق الأمان
**المجال:** Licensing & Runtime Protection
**آخر مراجعة:** 2026-09-12
**المصادر:** `server/_core/license.ts`، `server/_core/license/helpers.ts`، `server/_core/license/validation.ts`، `server/_core/license/types.ts`، `server/_core/featureMiddleware.ts`، `server/_core/heartbeat.ts`، `server/_core/centralLicenseRequest.ts`، `server/routers/license.ts`

> هذا مرجع تقني للسلوك الحالي. لا يحتوي مفاتيح خاصة أو تراخيص أو Hardware IDs حقيقية، ولا يمثل رأيًا قانونيًا أو ضمانًا أمنيًا مستقلًا.

## 1. دورة ملف الترخيص

يقرأ النظام ملف `license.json` من أول مسار متاح بالترتيب التالي:

1. `LICENSE_PATH`، ويُحل المسار النسبي من مجلد التشغيل.
2. `TENANT_ROOT/license.json`.
3. `tenants/{TENANT_ID أو tenant-sgh}/license.json`.

يتطلب parser وجود `key` و`hardwareId` و`expiryDate` و`features` في ملف الترخيص. أما التحقق التشفيري فيستخدم envelope مشفرًا بـBase64 يحتوي `payload` و`signature`، ويقرأ المفاتيح العامة من `license-keys/public-key.pem` و`previous-public-key.pem` مع مسار legacy اختياري.

## 2. التوقيع والتحقق

الترخيص يستخدم **توقيعًا رقميًا** وليس تشفيرًا لمحتوى الترخيص. يتحقق النظام من التوقيع باستخدام RSA-PSS مع SHA-256 وsalt بطول digest. تُجرب المفاتيح العامة الحالية والسابقة، ما يدعم تدوير المفتاح العام دون كشف المفتاح الخاص.

بعد نجاح التوقيع يتحقق النظام من:

- Hardware ID.
- النطاق إذا تم ضبط `LICENSE_DOMAIN` أو `BOCAM_PUBLIC_URL` أو `SERVER_URL`.
- تاريخ الانتهاء بصيغة Unix timestamp.
- وجود ميزة واحدة على الأقل.

تعاد `LicenseInfo` بقيمة `isValid: false` عند فشل هذه الشروط. لا تستنتج هذه القيمة وحدها أن عملية الخادم ستتوقف.

## 3. Hardware ID والنطاق

يُستخرج Hardware ID من MAC لواجهة شبكة IPv4 غير داخلية، بعد إزالة النقط وتحويل القيمة إلى أحرف كبيرة. توجد مصادر fallback هي `LICENSE_HARDWARE_ID` وHardware ID الموجود في ملف الترخيص عندما تتوفر واجهة شبكة، ثم أول MAC صالح متاح.

لذلك قد يتغير Hardware ID عند تغيير البيئة أو واجهة الشبكة أو إعدادات الحاوية. لا ينبغي وصفه بأنه معرف ثابت أو فريد مطلقًا.

يُقارن النطاق المرخص بالنطاق المطبّع من أول قيمة متاحة بين `LICENSE_DOMAIN` و`BOCAM_PUBLIC_URL` و`SERVER_URL`. إذا لم تُضبط أي منها، لا يطبق فحص النطاق.

## 4. بدء التشغيل وحالة الترخيص

`initializeLicense(false)` يرمي خطأ عند غياب ملف الترخيص أو فشل التهيئة. أما `initializeLicense(true)` فيسمح ببدء الخادم مع رسالة activation mode عند غياب الملف ويعيد `null`.

`validateLicense()` يعيد معلومات ترخيص غير صالحة في حالات الفشل المعتادة بدل إنهاء العملية مباشرة. لذلك:

- التحقق المحلي موجود ويعمل دون اتصال مركزي أثناء قراءة الملف والتحقق من التوقيع.
- Kill Switch الذي يوقف الخادم دائمًا **غير مثبت كسلوك عام في المسار الحالي**.
- لا يجوز وصف activation mode أو `isValid: false` بأنه إيقاف تلقائي مؤكد.
- أي قرار لتغيير هذا السلوك هو تغيير أمني مستقل خارج نطاق تحديث الوثائق.

## 5. Feature Gates

على الخادم، `requireFeature` و`requireFeatureWithAdminBypass` يقرآن حالة الميزة من الترخيص ويرميان `FORBIDDEN` عند عدم تحقق الشرط. يدعم الأول شرط كل الميزات أو أي ميزة، ويدعم الثاني تجاوزًا للمستخدم ذي الدور `admin`.

في الواجهة، تستخدم `FeatureGate` و`ProtectedRoute` و`useLicense` حالة الترخيص لإخفاء أو قفل الميزات. هذه الحواجز لا تستبدل حماية `protectedProcedure` أو `permissionProcedure` ولا تثبت صلاحية RBAC.

## 6. Heartbeat والسجلات المحلية

يُبنى endpoint heartbeat من `IDEA_HUB_URL` إلى `/api/heartbeat/bocam`. عند غياب المتغير لا تُرسل النبضة. تستخدم عملية الإرسال مهلة 10 ثوانٍ، وعند فشل الشبكة أو استجابة غير ناجحة تسجل الفشل وتعيد `false` دون إيقاف الخادم.

ترسل النبضة بيانات تشغيلية تشمل Hardware ID ومفتاح الترخيص الموقع وإصدار الترخيص والحالة والطابع الزمني و`IDEA_HUB_SYSTEM_ID` واسم النسخة ورابطها العام. يجب التعامل مع هذه البيانات باعتبارها حساسة تشغيليًا.

يحتفظ `.heartbeat-log` بآخر 30 سجلًا، ويخزن `.last-successful-run` وقت آخر تشغيل وHardware ID بصلاحيات ملف `0600`. هذا المرجع لا يثبت وجود آلية فعالة لمنع التلاعب بالساعة أو Kill Switch مركزي.

## 7. الطلبات المركزية والدعم

تستخدم الطلبات المركزية `IDEA_HUB_URL` و`IDEA_HUB_SYSTEM_ID`. تحفظ الطلبات المعلقة محليًا في ملفات مؤقتة بصلاحيات `0600`، وتُحذف بعد الانتهاء أو انتهاء الصلاحية. يتم استبدال الملف المؤقت ذريًا عبر rename.

قبل إنشاء طلب دعم، يتحقق النظام محليًا من صلاحية الترخيص ويستخدم بصمة SHA-256 للمفتاح الموقع بدل إرسال المفتاح ضمن بيانات التشخيص العامة. قد تتضمن diagnostics مقاييس تشغيلية ومرفقات محددة الأنواع؛ يجب عدم تضمين أسرار أو بيانات مرضى.

بعد تثبيت ملف مركزي، يجب إعادة التحقق منه، وعند الفشل يُحذف الملف غير الصالح وفق مسار الخدمة الحالي.

## 8. إجراءات license router

الإجراءات العامة تعرض حالة الترخيص وHardware ID والميزات ووجود الملف وحالة طلب التفعيل المركزي، كما تسمح بإنشاء طلب الترخيص أو طلب تفعيل ميزة قبل تسجيل الدخول. `getStatus` و`checkFeatures` محميان بتسجيل الدخول.

هذه الإتاحة العامة قرار تصميم قائم حاليًا وليست توصية أمنية. يجب مراجعة مقدار البيانات المكشوفة في قرار أمني مستقل، خصوصًا Hardware ID ورسائل الفشل.

## 9. حدود الاختبارات

تغطي اختبارات الترخيص الحالية أجزاء من التحقق، تدوير المفاتيح، Feature Middleware، الطلبات المركزية، وراوتر الترخيص. لا يثبت ذلك دورة إنتاج كاملة أو اتصال heartbeat حقيقيًا أو سياسة قانونية أو امتثالًا تنظيميًا.

عند توثيق نتيجة اختبار، يجب ربطها بسلوك محدد وعدم تحويل نجاح اختبار وحدة إلى ضمان شامل للتشغيل الإنتاجي.

## 10. قرارات مؤجلة

- `R4-01`: اعتماد ما إذا كان Kill Switch مطلوبًا وتغيير سلوكه في مسار أمني مستقل.
- `R4-02`: توحيد أو إبقاء مصدر heartbeat القائم على `IDEA_HUB_URL`.
- `R4-03`: سياسة Hardware ID للأجهزة الافتراضية والحاويات.
- `R4-04`: مراجعة ما يجوز كشفه من إجراءات license العامة.
- `R4-05`: مراجعة قانونية مستقلة لملكية المكونات والامتثال، دون اعتبار هذا المرجع رأيًا قانونيًا.
