# دليل ترخيص BOCAM CRM

**الحالة:** `working`  
**الجمهور:** المسؤولون والمطورون  
**المجال:** Licensing  
**آخر مراجعة:** 2026-09-12

هذا الدليل يجمع الإرشادات العامة وأوامر إدارة الترخيص. المرجع التقني للسلوك الفعلي هو [مرجع تشغيل الترخيص وحماية التشغيل](./LICENSE_RUNTIME_REFERENCE.md). لا يمثل هذا المستند رأيًا قانونيًا أو ضمانًا للامتثال، وأي نص قانوني أو تجاري يحتاج مراجعة مالك المشروع والمستشار المختص.

## الترخيص القانوني

ملف [LICENSE](../../LICENSE) هو المصدر المرجعي لترخيص المستودع. لا يُستنتج من وجود نظام Feature Gate أن جزءًا محددًا من الكود يحمل ترخيصًا تجاريًا منفصلًا. أي تقسيم بين مكونات مفتوحة أو تجارية، وحقوق Idea Hub أو BOCAM، وشروط إعادة التوزيع يجب اعتماده في وثيقة قانونية منفصلة.

## نموذج الترخيص التقني

يقرأ النظام `license.json` من `LICENSE_PATH`، ثم `TENANT_ROOT/license.json`، ثم `tenants/{TENANT_ID أو tenant-sgh}/license.json`. يحتوي الملف على مفتاح موقع وبيانات Hardware ID وتاريخ انتهاء وميزات. يستخدم التحقق RSA-PSS مع SHA-256 ومفتاحًا عامًا، وليس تشفيرًا لمحتوى الترخيص.

تشمل عملية التحقق Hardware ID والانتهاء والميزات، ويُفحص النطاق فقط عند ضبط `LICENSE_DOMAIN` أو `BOCAM_PUBLIC_URL` أو `SERVER_URL`. التفاصيل وقواعد الفشل موثقة في [المرجع التقني](./LICENSE_RUNTIME_REFERENCE.md).

## أوامر الإدارة

### قراءة Hardware ID

```bash
pnpm license:get-hardware-id
```

لا تُدرج قيمة Hardware ID حقيقية في الوثائق أو البلاغات العامة.

### توليد مفاتيح التوقيع

```bash
pnpm license:generate-keys
```

يجب حفظ المفتاح الخاص خارج المستودع وعدم مشاركته. المفتاح العام فقط مطلوب للتحقق داخل نسخة التشغيل.

### توليد ترخيص

```bash
pnpm license:generate <HARDWARE_ID> <EXPIRY_TIMESTAMP> "<FEATURES>"
```

مثال اصطناعي فقط:

```bash
pnpm license:generate EXAMPLEHARDWAREID 1811376000 "whatsapp,reports"
```

الميزات يحددها مولد الترخيص الفعلي؛ لا تفترض أن كل اسم ميزة يملك صفحة أو وحدة مستقلة. القيمة `*` تعني السماح العام بالميزات التي يفحصها النظام.

## التثبيت والتحقق

ضع ملف الترخيص في المسار الذي تحدده متغيرات البيئة، ثم شغّل مسار التطبيق المعتاد. عند وجود ملف صالح، يعيد التحقق `isValid: true`. عند الفشل، يعيد النظام معلومات ترخيص غير صالحة في عدة مسارات، وقد يسمح `initializeLicense(true)` ببدء الخادم في activation mode عند غياب الملف.

لذلك لا يُستخدم هذا الدليل لادعاء أن Kill Switch يوقف الخادم دائمًا. التغيير إلى إيقاف إلزامي قرار أمني مستقل وغير منفذ كقاعدة عامة في السلوك الحالي.

## Feature Gates

توجد حماية ميزات على الخادم عبر `requireFeature` و`requireFeatureWithAdminBypass`، وحواجز واجهة عبر `FeatureGate` و`ProtectedRoute` و`useLicense`. حارس الواجهة لا يحمي API، وadmin bypass لا يثبت صلاحية RBAC أو يغير ملف الترخيص.

## Heartbeat والطلبات المركزية

يستخدم heartbeat المتغير `IDEA_HUB_URL` ويرسل إلى `/api/heartbeat/bocam` بمهلة محددة، ويفشل بصمت عند أخطاء الشبكة دون إيقاف الخادم. يحتفظ النظام بآخر 30 سجلًا في `.heartbeat-log` ويحفظ وقت التشغيل في `.last-successful-run`.

تستخدم طلبات الترخيص والدعم المركزية `IDEA_HUB_URL` و`IDEA_HUB_SYSTEM_ID`، وتحفظ الطلبات المعلقة محليًا بملفات مؤقتة بصلاحيات `0600`. لا تستخدم `CENTRAL_ACTIVATION_URL` أو `CENTRAL_UPDATE_URL` كمتغيرات موثقة لهذا المسار ما لم يثبتها الكود الحالي.

## حماية البيانات

- لا تُرسل مفاتيح خاصة أو تراخيص حقيقية إلى التذاكر أو الوثائق.
- لا تُدرج Hardware IDs حقيقية في الأمثلة أو تقارير عامة.
- لا تضع بيانات مرضى أو أسرارًا داخل المرفقات أو diagnostics.
- راجع مقدار البيانات التي تعرضها إجراءات license العامة قبل نشر النظام.

## حدود التحقق

اختبارات الترخيص تغطي أجزاء من validation وتدوير المفاتيح وFeature Middleware والطلبات المركزية وراوتر الترخيص. لا تثبت هذه الاختبارات وحدها تشغيلًا إنتاجيًا كاملًا أو heartbeat مركزيًا حقيقيًا أو حماية من التلاعب بالساعة أو التزامات قانونية.
