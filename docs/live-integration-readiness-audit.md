# تدقيق الجاهزية للتكامل الحي مع Meta والمنصات الاجتماعية

**تاريخ التدقيق:** 19 أغسطس 2026  
**النطاق:** الخادم، قاعدة البيانات، واجهات الإدارة، وموصلات Meta وWhatsApp وX وLinkedIn وYouTube وTikTok.  
**الهدف:** تجهيز البوابة تقنياً للربط الحقيقي لاحقاً من دون إدخال أي اعتماد إنتاجي في هذه المرحلة.

## الحكم التنفيذي

المشروع يملك أساساً متقدماً لإدارة المحتوى، صندوق البريد الموحد، Webhooks الخاصة بـ Meta، إجراءات التعليقات، وWhatsApp. كما أن جداول النشر والجدولة ومهمة Heartbeat موجودة ومطبقة في قاعدة البيانات. لكنه **ليس جاهزاً بعد لتشغيل تكامل خارجي حي كامل**، لأن طبقة التفويض OAuth وحفظ التوكنات المجددة وربط الأصول والحسابات، وكذلك موصلات التوزيع الفعلية، لم تُنفذ بعد.

> **التمييز المهم:** الصفحة الحالية تستطيع حفظ بيانات التطبيقات بصورة مشفرة، ويمكنها إظهار أن المنصة «جاهزة لـ OAuth». لكنها لا تبدأ OAuth، ولا تستقبل callback، ولا تخزن Access أو Refresh Tokens، ولا ترتبط بحساب أو صفحة أو قناة قابلة للنشر.

## نتيجة الفحص حسب المجال

| المجال | الوضع | ما هو متاح فعلياً | الفجوة قبل التشغيل الحي |
|---|---|---|---|
| إعدادات تطبيق Meta | **مكتمل جزئياً** | تخزين مشفر لـ App ID وApp Secret وVerify Token وPage Access Token ومعرفات الصفحة وInstagram. | لا يوجد ربط Meta Business عبر OAuth، اختيار أصول، فحص صلاحيات حي، تجديد توكن، أو شاشة تفويض ومتابعة مراجعة التطبيق. |
| Webhook الخاص بـ Meta | **جاهز وظيفياً** | تحقق، توقيع HMAC، منع تكرار، تطبيع، سجل للحمولات، ورسائل Messenger وInstagram وتعليقات Facebook وInstagram. | يلزم اشتراك حي بالأصول، مراقبة إخفاقات، إعادة معالجة آمنة، ولوحة تشخيص للاشتراكات والتوكنات. |
| صندوق البريد الموحد | **مكتمل لطبقة Meta فقط** | حسابات ومحاور وعناصر ورسائل وتعليقات، تعيين، متابعة، بحث، صلاحيات، وسياقات تعليقات. | نماذجه تقبل X وLinkedIn وYouTube، لكن لا يوجد Webhook أو موصل مزامنة أو إرسال فعلي لهذه المنصات. |
| إجراءات تعليقات Meta | **مكتمل جزئياً** | الرد العام، الإخفاء/الإظهار، الرسالة الخاصة حيث تسمح المنصة، والإثراء الخادمي. | يحتاج توكنات الأصول الحية، فحص Scope قبل الإجراء، معالجة انتهاء التوكن، وحدود معدلات الاستخدام ومراقبة أخطاء Graph API. |
| WhatsApp Cloud API | **قوي لكن غير موحد** | صفحات رسائل، قوالب، جودة الحساب والرقم، امتثال، opt-in، Webhooks، SSE، اتصالات ومهام خدمة. | الاعتماد الحالي على متغيرات بيئية لرقم الهاتف وAccess Token؛ لا توجد واجهة تسجيل مضمّن أو تخزين اتصال موحد قابل للتدوير ومشاركة الأصول. |
| النشر متعدد المنصات | **سير عمل مكتمل، توزيع حي غير منفذ** | مسودات، موافقات، وسائط، وجهات، محاولات، جدولة وHeartbeat. | لا توجد موصلات نشر حقيقية لـ Facebook أو Instagram أو X أو LinkedIn أو YouTube أو TikTok. معالج Heartbeat يلتقط المنشور ثم يعيده للحالة المجدولة كـ «متجاوز»، ولا ينفذ رفعاً أو نشراً خارجياً. |
| إعدادات X وLinkedIn وYouTube وTikTok | **إعداد تطبيق فقط** | حفظ Client ID وClient Secret وScopes مشفرة لكل منصة وعرض الحالة `ready_for_oauth`. | لا توجد مسارات بدء OAuth أو callback أو PKCE/state أو حفظ توكنات أو استعلام أصول أو موصل نشر أو مزامنة. |
| قاعدة بيانات النشر | **هيكل جيد مع نقص حرج** | جداول الحسابات، المنشورات، الوسائط، الوجهات، المحاولات والفهارس موجودة في قاعدة البيانات الفعلية. | لا توجد جداول عامة لاتصالات OAuth أو توكنات مشفرة أو أصول خارجية أو حالات OAuth أو اشتراكات Webhook أو outbox موزع. |
| قياس Meta Pixel وConversions API | **جزئي** | مكوّن Pixel ومساعد CAPI خادمي لأحداث Lead وSchedule وCompleteRegistration. | الاعتمادات محفوظة في متغيرات بيئية، لا توجد إدارة Dataset/Pixel من الواجهة أو شاشة جودة الأحداث وDeduplication وتشخيص Events Manager. |
| Lead Ads وMarketing API | **غير منفذ** | توجد جداول Leads وحملات داخلياً، وقابلية ربط مفاهيمية مع النشر. | لا يوجد Leadgen Webhook أو استرجاع نموذج ولا ربط Ad Account أو Insights أو تقارير إعلان أو نسب مصدر الحملة. |

## ما تحقق في قاعدة البيانات الفعلية

تحقق الفحص غير المدمر من وجود الجداول التالية في قاعدة بيانات المشروع: `meta_integration_settings`، و`social_platform_integration_settings`، وجداول صندوق البريد الموحد، وجداول النشر الستة، إضافة إلى `whatsapp_webhook_events` و`whatsapp_contacts` و`whatsapp_user_opt_ins`. هذا يؤكد أن ترحيلات طبقات Meta وصندوق البريد والنشر وإعدادات التطبيقات قد طبقت بالفعل.

| نموذج موجود | دوره | التقييم |
|---|---|---|
| `meta_integration_settings` | إعداد تطبيق Meta وخيارات Webhook المشفرة. | مناسب للبدء، لكنه لا يمثل اتصال OAuth متعدد الأصول. |
| `social_platform_integration_settings` | Client credentials للمنصات غير Meta. | مناسب لإعداد التطبيقات، وليس لإدارة حسابات حية. |
| `social_inbox_*` | تخزين موحد للحسابات والمحادثات والعناصر وسجل Webhook. | مناسب لتوسعة الموصلات بعد بناء كل مزود. |
| `social_publish_*` | دورة المحتوى والموافقات والوجهات والمحاولات. | مناسب للتوزيع، لكنه يحتاج اتصالاً موثقاً وموصلات تنفيذ. |
| `whatsapp_*` | الرسائل والقوالب والجودة والامتثال والأحداث والاتصالات. | غني وظيفياً، ويحتاج توحيد الاعتمادات والتسجيل المضمن. |

## الجداول والطبقات الخادمية المطلوب إضافتها

لا أوصي بوضع Access Token أو Refresh Token داخل `social_publish_accounts` مباشرة. الأفضل هو فصل الاتصال والأصل والتوكن حتى يمكن ربط أصل واحد بمهام متعددة، ودعم التجديد والإلغاء والتدقيق بأمان.

| المكون المقترح | المسؤولية | الحقول الأساسية |
|---|---|---|
| `integration_connections` | سجل اتصال واحد مع كل مزود وحساب أعمال. | provider، حالة الاتصال، owner، scopes، انتهاء الصلاحية، آخر تحقق، آخر خطأ. |
| `integration_connection_tokens` | حفظ التوكنات المشفرة وبيانات التجديد. | connectionId، accessTokenEncrypted، refreshTokenEncrypted، expiresAt، encryptionKeyVersion، tokenType. |
| `integration_external_assets` | ربط الأصول التي يعيدها المزود. | connectionId، assetType، externalId، displayName، capabilities، metadata، active. |
| `integration_oauth_states` | حماية بدء OAuth وPKCE وعودة callback. | provider، stateHash، codeVerifierEncrypted، redirectUri، userId، expiresAt، consumedAt. |
| `integration_webhook_subscriptions` | حالة الاشتراك في Page أو WABA أو حساب آخر. | assetId، callbackUrl، subscribedFields، status، verifiedAt، lastEventAt، lastError. |
| `integration_delivery_jobs` | Outbox موثوق لتوزيع المحتوى الخارجي. | destinationId، runAfter، status، attempts، leaseUntil، lastError، idempotencyKey. |
| `integration_audit_events` | سجل عمليات آمن لا يحتوي أسراراً أو محتوى حساساً. | provider، action، actorUserId، connectionId، correlationId، result، sanitizedSummary. |
| توسعة `social_publish_destinations` | تثبيت نسخة النشر والوسائط المتوافقة لكل منصة. | payloadSnapshot، mediaValidation، nextRetryAt، processingState، providerRequestId. |

## الواجهات: ما يبقى وما يتغير وما يضاف

| الواجهة | القرار | التحديث المطلوب |
|---|---|---|
| **إعدادات الربط العامة** الحالية | **تحديث جوهري** | تقسيمها إلى تبويبات: تطبيقات المزود، الحسابات والأصول المتصلة، Webhooks، الصلاحيات والصحة، وسجل العمليات. يحتفظ تبويب التطبيقات بحفظ Client Secret الحالي. |
| **صفحة حسابات اجتماعية متصلة** | **إضافة جديدة** | بطاقات لكل اتصال: «ربط»، «إعادة تفويض»، «إلغاء ربط»، الأصل المختار، Scopes، الانتهاء، الصحة، آخر خطأ، وقدرات النشر/الرسائل. |
| **معالج ربط Meta** | **إضافة جديدة** | يبدأ Facebook Login for Business، يعالج العودة، ثم يتيح اختيار Page وInstagram وAd Account وPixel/Dataset وربط Webhook. |
| **معالج ربط WhatsApp** | **إضافة جديدة أو دمج في اتصال WhatsApp** | زر «ربط WhatsApp Business»، حالة التسجيل المضمن، WABA والرقم والقوالب وWebhook والحدود والجودة. |
| **اتصال WhatsApp** الحالي | **تحديث** | استبدال رسالة متغيرات البيئة بتدفق اتصال آمن؛ تبقى معلومات الصحة والتشخيص والقوالب. |
| **النشر متعدد المنصات** | **تحديث جوهري** | زر ربط عند غياب الحساب، فاحص توافق قبل الموافقة، اختيار أصل محدد وليس المنصة فقط، إعدادات لكل منصة، معاينة حقيقية، تقدم الرفع والمعالجة، إعادة محاولة آمنة وسجل محاولة مفهوم. |
| **صندوق البريد الموحد** | **تحديث تدريجي** | فلتر أصل متصل، مؤشر صلاحية التوكن، إعادة تفويض، إعداد قواعد توجيه، وحالة مزامنة لكل مزود عند إضافة X وLinkedIn وYouTube. |
| **مركز Lead Ads وقياس التحويل** | **إضافة جديدة** | مصادر العملاء المحتملين والنماذج والحملات، قائمة Leads واردة، قواعد التوجيه، جودة التكامل، حالة CAPI وPixel وDataset والأحداث الأخيرة. |
| **عمليات التكامل والسجل** | **إضافة جديدة** | سجل محاولات OAuth وWebhook والنشر وCAPI، فلاتر زمنية، correlation ID، أخطاء مصنفة، وزر إعادة محاولة مأمون. |

## ترتيب التجهيز قبل إدخال الاعتمادات الحقيقية

### P0 — بنية الاتصال الآمنة

تنفذ أولاً ترحيلات الاتصالات والتوكنات والأصول وOAuth state وWebhook subscriptions وسجل التدقيق. ثم تبنى طبقة موحدّة `IntegrationConnectionService` لها واجهة مزود موحدة، وتطبق Facebook Login for Business وWhatsApp Embedded Signup. هذه المرحلة لا تنشر محتوى ولا تستقبل بيانات إنتاجية إلا بعد اختبار Sandbox، لكنها تجعل خادم المشروع وقاعدة بياناته جاهزين للربط الحقيقي بشكل صحيح.

### P1 — القيمة التشغيلية الأساسية لـ Meta

بعد P0 تنفذ موصلات Facebook وInstagram للنشر الفعلي من صفحة النشر، وتبدل Heartbeat من فحص وجدولة فقط إلى استهلاك `integration_delivery_jobs` وإجراء الرفع والنشر وإعادة المحاولة. بالتوازي يضاف Lead Ads إلى CRM وConversions API بصفحة تشخيص. عند نهاية هذه المرحلة يكون تسلسل «إعلان ← Lead ← متابعة WhatsApp ← حجز ← قياس تحويل» قابلاً للتشغيل والتدقيق.

### P2 — المنصات الأخرى

تستخدم طبقة OAuth الموحدة نفسها لبناء X، LinkedIn، YouTube وTikTok. تبدأ كل منصة بالربط والتحقق من الحساب والنشر اليدوي لعنصر اختبار، ثم تضيف الجدولة والوسائط والحالات الخاصة بالمنصة. لا يبدأ العمل بها قبل إكمال P0 لأن تخزين التوكنات والـ callback وعمليات الإلغاء والتشخيص مشتركة.

### P3 — التحليلات والإدارة المتقدمة

تضاف Marketing API وInsights وThreads وإدارة الحملات وقواعد الإعلان بعد ثبات الاتصالات والقنوات التشغيلية. في بيئة صحية يجب أن تظل أحداث التسويق عامة، ولا تنقل أي تشخيص أو نتيجة أو محتوى محادثة سريرية إلى منصة الإعلانات.

## معايير جاهزية الربط الحقيقي

قبل أن تدخل المؤسسة أي اعتماد حي أو تضغط «ربط»، يجب أن تتحقق الشروط التالية:

| المعيار | حالة اليوم | شرط القبول |
|---|---|---|
| OAuth وPKCE وstate | غير موجود | callback محمي وتجارب انتهاء state وإعادة التفويض تعمل. |
| توكنات مشفرة قابلة للتجديد | غير موجود | لا يظهر توكن في الواجهة أو السجل، ويمكن اختبار انتهاء وتجديد وإبطال التوكن. |
| اختيار أصل مفوض | غير موجود | كل Page/Instagram/WABA/Ad Account/Channel مربوط باتصال محدد وقدراته معروضة. |
| النشر الخارجي | غير موجود | اختبار منشور حي محدد ومراقب لكل مزود، بمعرف خارجي ورابط ومحاولة محفوظة. |
| Webhook والتعافي | جزئي | اشتراك حي، صحة محدثة، deduplication، قائمة إخفاقات وإعادة معالجة. |
| قيود المحتوى والوسائط | جزئي | تحقق سابق للنشر لنوع المحتوى والحجم والأبعاد ومدة الفيديو وسياسات المنصة. |
| الخصوصية والامتثال | جزئي | فصل بيانات التسويق عن السجل الطبي، Opt-in قابل للتدقيق، ومراجعة قانونية قبل أحداث التحويل أو الحملات. |
| المراقبة | جزئي | تنبيهات انتهاء التوكن وفشل webhook وفشل النشر ومعدل الأخطاء، وسجل عمليات قابل للبحث. |

## التوصية العملية

لا تبدأ بإدخال أسرار أو توكنات حية الآن. ابدأ بتنفيذ **P0** كاملاً: طبقة اتصال موحدة، ترحيلات التوكنات والأصول، معالج Meta، ومعالج WhatsApp. بعدها نستخدم الحسابات الحقيقية مرة واحدة في تدفق تفويض رسمي، بدلاً من الاعتماد على نسخ الرموز يدوياً أو حفظها في متغيرات البيئة. هذا يقلل خطر انتهاء التوكن أو فقدان الأصل أو كشف السر، ويجعل بقية المنصات إضافات منظمة إلى نفس البنية بدلاً من حلول منفصلة.
