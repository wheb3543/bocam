# مخطط صفحة النشر متعددة المنصات

## الهدف التشغيلي

تدير الصفحة المحتوى من **مسودة واحدة** إلى عدة وجهات نشر مستقلة. ينشئ محرر المحتوى النص والوسائط والبيانات الوصفية، ثم يضبط لكل منصة نسخة قابلة للتعديل وخياراتها. ولا يستدعي المتصفح أي واجهة خارجية؛ يتعامل الخادم مع المحولات والتوكنات المشفرة وسجل التدقيق.

## نموذج البيانات

| الكيان | الغرض | الحقول المحورية |
|---|---|---|
| `social_publish_accounts` | حساب/صفحة/قناة متصلة أو في انتظار الربط | المنصة، نوع الحساب، المعرف الخارجي، الاسم، الحالة، القدرات، آخر خطأ، بيانات الاتصال المشفرة لاحقاً |
| `social_publish_posts` | قطعة المحتوى المركزية ومسار الموافقة | العنوان، النص الأساسي، نوع المحتوى، الحالة، موعد النشر، المنطقة الزمنية، الحملة، منشئ المحتوى، قرار الموافقة، معرف مهمة الجدولة |
| `social_publish_post_media` | ترتيب مراجع مكتبة الوسائط أو رابط خارجي لكل مسودة | معرف الوسائط، الدور (رئيسي/غلاف/ترجمة)، الترتيب، البديل، حالة صلاحية الأصل |
| `social_publish_destinations` | نسخة المنصة وحالة توزيعها المستقلة | الحساب، المنصة، النص الخاص، إعدادات المنصة، الحالة، المعرف/الرابط الخارجي، وقت المحاولة، الخطأ، عداد المحاولات |
| `social_publish_attempts` | سجل تدقيق لا يقبل الكتابة فوقه | الوجهة، العملية، الحالة، رمز الاستجابة، معرف التتبع، الطلب أو الاستجابة بعد حجب الأسرار، المنفذ، الوقت |

## حالات سير العمل

| الحالة | المعنى | الانتقال المسموح |
|---|---|---|
| `draft` | محتوى قابل للتعديل ولم يُرسل للمراجعة | طلب موافقة، حفظ، إلغاء |
| `in_review` | ينتظر قرار مسؤول | موافقة أو رفض أو إرجاع للمسودة |
| `approved` | جاهز للنشر أو الجدولة | نشر فوري أو جدولة أو إرجاع للمسودة |
| `scheduled` | محفوظ بموعد ووجهات محددة | إلغاء الموعد أو تنفيذ المهمة وقت الاستحقاق |
| `publishing` | الخادم ينفذ الوجهات تدريجياً | نجاح كلي أو نجاح جزئي أو فشل |
| `published` / `partial_failed` / `failed` | نتيجة غير قابلة للالتباس لكل وجهة | إعادة محاولة للوجهات الفاشلة فقط |

## التحويلات الرسمية

يمتلك كل محول دالة مستقلة للتحقق من القدرة ورفع الأصل وإنشاء المحتوى والاستعلام عن حالته. تستقبل الدالة `destination` و`post` و`media` وتعيد معرفاً خارجياً أو خطأً مصنفاً. يظل تنفيذ المحولات الحية معطلاً حتى يحفظ المسؤول OAuth أو التوكنات والصلاحيات لكل منصة؛ الواجهة لا تدّعي اتصال حساب غير مفعّل.

| المحول | سير العمل |
|---|---|
| Meta | التحقق من إعدادات Meta المشفرة، إنشاء حاوية Instagram أو جلسة Facebook Reel، انتظار المعالجة، ثم النشر وحفظ المعرف والرابط. |
| X | رفع الوسيط، انتظار معالجة الفيديو المجزأ عند الحاجة، ثم تمرير `media_ids` إلى إنشاء المنشور. |
| LinkedIn | تهيئة الأصل للحصول على URN، الرفع إلى الرابط المؤقت، انتظار الحالة، ثم إنشاء Post مع URN. |
| YouTube | رفع قابل للاستئناف مع بيانات الفيديو ثم متابعة حالة المعالجة والخصوصية أو موعد النشر. |
| TikTok | استعلام معلومات المنشئ، التحقق من الخصوصية والإذن، تهيئة النشر وحفظ `publish_id` ثم متابعة النتيجة. |

## الجدولة وإعادة المحاولة

يحفظ جدول المنشورات موعداً صريحاً في UTC ومنطقة العرض الأصلية، ولا يستخدم مؤقتاً داخل العملية. عند تفعيل الجدولة الحية، ينشئ الخادم مهمة Heartbeat لكل مسودة مجدولة ويخزن `scheduleCronTaskUid`. يستدعي المعالج `/api/scheduled/social-publish`، ويتحقق من هوية المهمة، ثم يقفل المنشور من `scheduled` إلى `publishing` قبل أي طلب خارجي. هذا القفل ومعرف idempotency لكل وجهة يمنع النشر المضاعف عند إعادة تسليم المهمة. لا ينشئ النظام هذه المهمة قبل نشر النسخة إلى بيئة الإنتاج وتوصيل OAuth المطلوب.

## الضوابط الأمنية

تُخزن أسرار المنصة وrefresh tokens مشفرة في الخادم ولا تُعاد إلى tRPC. وتستخدم كل محاولة سجلّاً منظفاً من التوكنات والروابط الموقّعة. يمنع الخادم النشر الفوري من حالة غير `approved`، ويقصر الموافقة والإلغاء على الأدوار المخولة. كما يتحقق من نوع الوسيط ومدته وأبعاده قبل تسليمه إلى المحول بدلاً من إرسال ملف غير متوافق إلى المنصة.

## تجربة الواجهة

تحتوي الصفحة على محرر RTL، بطاقات اختيار المنصات، منتقي من مكتبة الوسائط، لوحة إعدادات خاصة بالمنصة، معاينة حالة كل وجهة، وجدول لمسودات النشر. يظل زر النشر الحي غير متاح عند عدم وجود حساب متصل أو موافقة أو وسائط متوافقة، ويعرض سبب التعطيل بوضوح. يستطيع المستخدم مع ذلك إنشاء المسودة وإرسالها للموافقة أو حفظ موعدها للاستعداد للربط الحي.
