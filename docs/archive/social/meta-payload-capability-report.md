# تقرير تحليل حمولات Meta لصندوق البريد الموحد

**النطاق:** رسائل Messenger وInstagram Professional، وتعليقات Facebook Pages وInstagram.  
**تاريخ التحليل:** 17 أغسطس 2026.  
**النتيجة المختصرة:** يستقبل النظام حالياً الحد الأدنى التشغيلي من الحقول لإنشاء محادثات ورسائل وتعليقات موحّدة، ويحفظ الحمولة الخام للتدقيق. لكنه لا يستفيد بعد من نسبة مهمة من حقول Meta ذات القيمة العملية، وخصوصاً **المرفقات المتعددة، التفاعلات، تعديلات وحذف التعليقات/الرسائل، بيانات الإحالة الإعلانية، وروابط المنشورات**.

> لا توجد صيغة JSON واحدة ثابتة لكل أحداث Meta؛ فالغلاف موحّد لكن محتوى `entry` يتغير بحسب الحقل المشترك فيه ونوع الحدث. لذلك يغطّي هذا التقرير الحمولات الكاملة ذات الصلة مباشرة بصندوق الرسائل والتعليقات، لا كل أحداث صفحات Meta الأخرى. [1] [2]

## 1. الغلاف المشترك للحمولات

كل حمولة تصل بصيغة JSON موقّعة في الرأس `X-Hub-Signature-256`. يحتوي الجذر على `object`، ثم `entry[]` التي قد تضم أكثر من حدث. يمثل `entry.id` حساب الصفحة أو حساب Instagram Professional، ويعكس `entry.time` وقت إرسال Meta للإشعار وليس بالضرورة وقت إنشاء التفاعل. [1] [2]

```json
{
  "object": "page | instagram",
  "entry": [
    {
      "id": "PAGE_OR_INSTAGRAM_ACCOUNT_ID",
      "time": 1710000000000,
      "messaging": ["... أحداث الرسائل ..."],
      "changes": ["... أحداث التعليقات ..."]
    }
  ]
}
```

| الحقل | فائدته التشغيلية | وضع النظام الحالي |
|---|---|---|
| `object` | اختيار منصة المصدر (`page` أو `instagram`) | **مستفاد منه** لتحديد Messenger/Facebook/Instagram. |
| `entry.id` | ربط الحدث بالحساب المخزن | **مستفاد منه** كـ `accountExternalId`. |
| `entry.time` | وقت احتياطي للترتيب | **مستفاد منه** عند غياب وقت الحدث التفصيلي. |
| مجموعة `entry[]` | معالجة دفعات أحداث متعددة | **مستفاد منها**؛ المطبع يمر على جميع الإدخالات. |
| الحمولة الأصلية | تدقيق أو إعادة استخراج حقول جديدة لاحقاً | **محفوظة** في سجل الأحداث وفي عنصر الصندوق، لكنها غير قابلة للعرض أو الاستعلام المنظم من الواجهة حالياً. |

## 2. حمولة رسالة Messenger أو Instagram

تصل الرسائل ضمن `entry.messaging[]`. تحدد حقول `sender.id` و`recipient.id` طرفي المحادثة، ويحدد `timestamp` وقت الرسالة، فيما يحمل `message.mid` معرفها الفريد. يمكن أن تضم الرسالة نصاً، وعدة مرفقات، ورداً مضمناً، وإحالة من إعلان أو رابط دخول. [1] [3]

```json
{
  "sender": { "id": "SENDER_SCOPED_ID" },
  "recipient": { "id": "BUSINESS_ACCOUNT_ID" },
  "timestamp": 1710000000123,
  "message": {
    "mid": "MESSAGE_ID",
    "text": "نص الرسالة",
    "attachments": [
      {
        "type": "image | video | audio | file | sticker | reel | ig_reel | post | ig_post | appointment_booking | fallback",
        "payload": { "url": "https://...", "title": "...", "id": "..." }
      }
    ],
    "quick_reply": { "payload": "OPTION_ID" },
    "reply_to": { "mid": "PARENT_MESSAGE_ID", "is_self_reply": false },
    "referral": {
      "ref": "CAMPAIGN_REF",
      "ad_id": "AD_ID",
      "source": "ADS",
      "type": "OPEN_THREAD",
      "ads_context_data": {
        "ad_title": "...",
        "photo_url": "...",
        "video_url": "...",
        "post_id": "...",
        "product_id": "..."
      }
    },
    "is_echo": false,
    "is_self": false,
    "is_deleted": false,
    "is_unsupported": false
  }
}
```

| بيانات الرسالة | الاستخدام المقترح في صندوق البريد | الخادم الحالي | قاعدة البيانات الحالية | الواجهة الحالية |
|---|---|---|---|---|
| `sender.id` و`recipient.id` | تعريف العميل والطرف التجاري وربط السلسلة | **يستخرجها** | يحفظ معرف الكاتب/المشارك | يعرض اسماً عاماً غالباً؛ لا توجد بطاقة ملف شخصي. |
| `timestamp` و`mid` | ترتيب دقيق ومنع تكرار الرسالة | **يستخرجهما** | `externalPublishedAt` و`externalItemId` | يعرض الوقت. |
| `text` | نص الفقاعة والمعاينة والبحث | **يستخرجه** | `content` و`preview` | **يعرض ويبحث**. |
| `is_echo` | تمييز الصادر عن فريق العمل | **يستخدمه** لتحديد الاتجاه | `direction` و`status` | يعرض الرسالة الصادرة بلون مختلف. |
| `is_deleted` | إخفاء أو وسم رسالة محذوفة | **يتجاهل الرسالة بالكامل** | لا يسجل حالة حذف | لا توجد علامة حذف. |
| `attachments[]` | معاينات الصور/الفيديو/الصوت/الملفات وتعددها | يستخرج **أول مرفق فقط** | `mediaUrl` واحد فقط، والحمولة الخام كاملة | لا يعرض معاينة للمرفق؛ يعرض نص «مرفق». |
| `reply_to` | ربط الرد برسالته الأصلية وإظهار مقتطف | يستخرج `mid` فقط | `parentExternalId` | غير معروض كاقتباس أو رابط للرسالة الأصلية. |
| `quick_reply.payload` | معرفة الخيار الذي اختاره العميل وتوجيه سير العمل | محفوظ خام فقط | لا حقل منظم | غير معروض. |
| `referral` وبيانات الإعلان | نسب المحادثة إلى حملة/إعلان/منتج وتحسين تقارير التسويق | محفوظ خام فقط | لا حقول منسوبة | غير معروض ولا يُستخدم في التقارير. |
| `is_self` و`is_unsupported` | تمييز رسائل اختبار Meta أو الوسائط غير المدعومة | محفوظ خام فقط | لا حقل منظم | غير معروض. |
| `appointment_booking` | تحويل طلب الحجز إلى مسار خدمة/مهمة | محفوظ كنوع مرفق فقط | لا حقول حجز منسوبة | لا توجد بطاقة موعد أو إجراء. |

### أحداث الرسائل المساندة

تقدم Meta أيضاً إشعارات مستقلة للتفاعلات (`reaction`)، القراءة (`read` أو `message_reads`)، التعديل (`message_edit`)، اختيارات الأزرار (`postback`) والإحالات (`messaging_referral`). تحتوي هذه الأحداث على معرف الرسالة (`mid`) والحالة أو المعلومة الجديدة، ويمكن أن تجعل الفقاعات أكثر دقة وتساعد فرق العمل في متابعة القراءة والتحويلات. [2]

**الوضع الحالي:** الخادم يطبع أحداث `message` فقط. لذلك تصل هذه الحقول إلى الحمولة الخام إن وصلت ضمن اشتراك واسع، لكنها لا تتحول إلى عناصر أو تحديثات ظاهرة في صندوق البريد.

## 3. حمولة تعليق Instagram Professional

يرسل Instagram تعليقاً على الوسيط ضمن `entry.field=comments` أو `changes[].field=comments`. يحمل التعليق معرفه، بيانات صاحب التعليق، النص، ومعرف الوسيط؛ وقد يحمل معلومات إعلان للوسائط المدفوعة. يظهر `parent_id` عندما يكون التفاعل رداً على تعليق آخر. [2]

```json
{
  "object": "instagram",
  "entry": [{
    "id": "INSTAGRAM_PROFESSIONAL_ACCOUNT_ID",
    "time": 1710000000,
    "changes": [{
      "field": "comments",
      "value": {
        "comment_id": "COMMENT_ID",
        "parent_id": "PARENT_COMMENT_ID",
        "from": { "id": "IG_SCOPED_USER_ID", "username": "username" },
        "text": "نص التعليق",
        "media": {
          "id": "MEDIA_ID",
          "ad_id": "AD_ID",
          "ad_title": "AD_TITLE",
          "original_media_id": "ORIGINAL_MEDIA_ID",
          "media_product_type": "REELS | FEED | STORY | ..."
        }
      }
    }]
  }]
}
```

| بيانات تعليق Instagram | الوضع الحالي | الاستفادة الكاملة المقترحة |
|---|---|---|
| `comment_id` و`parent_id` | محفوظان كمعرف العنصر ومرجعه الأب | عرض سلسلة ردود التعليق، والرد على التعليق الأب الصحيح. |
| `from.id` و`from.username` | محفوظان | إنشاء بطاقة صاحب التعليق وإظهار اسم المستخدم القابل للنسخ/الفتح. |
| `text` | محفوظ ويظهر | دعم كلمات مفتاحية، أولوية، ومهام متابعة. |
| `media.id` | يستخدم فقط لتجميع المحادثة | إضافة رابط/صورة معاينة للوسيط الأصلي وإظهار نوعه. |
| `media.media_product_type` | محفوظ خام فقط | شارة «Reel» أو «Story» أو «Feed» لتحديد سياق التفاعل. |
| `ad_id` و`ad_title` و`original_media_id` | محفوظة خام فقط إن وجدت | نسب التعليق إلى إعلان وحملة وتقرير أداء الحملة. |
| `live_comments` | غير مطبع | تبويب/شارة بث مباشر مع تحديثات فورية. |
| أحداث `mentions` | غير مطبعة | صندوق أولوية خاص بالمنشنات. |

## 4. حمولة تعليق Facebook Page

تعليقات Facebook تصل عادة ضمن `object=page` و`changes[].field=feed`، مع `value.item=comment`. يوفّر الحدث معرف التعليق والمنشور والتعليق الأب والكاتب والنص والوقت؛ وقد يتضمن معلومات إضافية للمنشور مثل الرابط الدائم والوسائط وحالة الإخفاء والفعل (`verb`). [4]

```json
{
  "object": "page",
  "entry": [{
    "id": "PAGE_ID",
    "time": 1710000000,
    "changes": [{
      "field": "feed",
      "value": {
        "item": "comment",
        "verb": "add | edit | delete | hide | unhide | remove",
        "comment_id": "COMMENT_ID",
        "parent_id": "POST_OR_PARENT_COMMENT_ID",
        "post_id": "POST_ID",
        "created_time": 1710000000,
        "edited_time": 1710000001,
        "from": { "id": "USER_ID", "name": "اسم المستخدم" },
        "message": "نص التعليق",
        "is_hidden": false,
        "permalink_url": "https://facebook.com/...",
        "photo": "https://...",
        "video": "https://...",
        "link": "https://..."
      }
    }]
  }]
}
```

| بيانات تعليق Facebook | الوضع الحالي | الاستفادة الكاملة المقترحة |
|---|---|---|
| `comment_id`, `post_id`, `parent_id`, `from`, `message`, `created_time` | **مطبع ومحفوظ** | إنشاء سلسلة تعليق وعرض الكاتب والوقت والنص. |
| `verb=add` | **مدعوم فقط** | يضيف تعليقاً جديداً كما يجب. |
| `verb=edit/edited/delete/remove/hide/unhide` | **غير مدعوم؛ يُتجاهل** | تحديث النص، وسم المحذوف/المخفي، وإخفاؤه من القائمة أو إبقاؤه في سجل التدقيق. |
| `permalink_url` | لا يستخرج | ملء `postUrl` الموجود أصلاً في جدول المحادثات وإظهار زر «فتح المنشور الأصلي». |
| `is_hidden` | لا يستخرج | شارة «مخفي» وإجراء مراجعة/إظهار. |
| `photo`, `video`, `link` | لا يستخرج | معاينة منشور أو وسائط في رأس سلسلة التعليقات. |
| `edited_time`, `reaction_type`, `feedback_target_id` | خام فقط | حالة «معدل»، مؤشرات تفاعل، وسياق إشراف أفضل. |

## 5. جاهزية طبقات SGH الحالية

| الطبقة | الجاهزية | التفاصيل |
|---|---|---|
| Webhook والتحقق | **جاهز** | يتحقق من HMAC-SHA256 على الجسم الخام، ويقبل GET للتحقق، ثم يقر POST سريعاً. |
| المطبع | **جاهز جزئياً** | يغطي الرسالة الأساسية وتعليقات Instagram/Facebook الجديدة فقط. |
| سجل الحدث الخام | **جاهز** | حفظ الحمولة مع `eventKey` فريد وحالة معالجة. |
| جداول الرسائل والتعليقات | **جاهزة جزئياً** | تخزن نصاً ومرفقاً واحداً ومرجعاً أباً وهوية الكاتب؛ لا توجد بنية للمرفقات المتعددة أو سمات الحدث. |
| واجهة صندوق البريد | **جاهزة جزئياً** | تعرض النص والوقت والمنصة والحالة؛ لا تعرض المرفق أو الاقتباس أو سياق المنشور أو مصدر الإعلان أو التفاعل. |
| الإرسال والرد | **غير منفذ** | الواجهة توضح أن الرد يتطلب موصل Graph API رسمي؛ لا يوجد mutation/خدمة إرسال حالياً. |

## 6. خطة التعديل لتحقيق الاستفادة الكاملة

| المرحلة | التعديل المطلوب | الأثر في واجهة صندوق البريد |
|---|---|---|
| الأولى: الوسائط والسياق | إنشاء جدول `social_inbox_attachments` متعدد الصفوف وربطه بالعنصر؛ استخراج كل مرفق وخصائصه؛ تخزين `postUrl` وسياق `media` | بطاقات صور/فيديو/ملفات، زر فتح المنشور، وشارة Reel/Story/Ad. |
| الثانية: دورة حياة الحدث | دعم `message_edit` و`reaction` و`read` و`postback` و`referral`، وتعليقات Facebook المعدلة/المحذوفة/المخفية | حالة تعديل/حذف، إيصال قراءة، رموز تفاعل، ومعلومة مصدر العميل/الإعلان. |
| الثالثة: الردود والتعليقات | موصل Graph API للإرسال والرد على تعليق Facebook/Instagram، مع سجل حالة الإرسال ومعالجة الأخطاء | محرر رد حقيقي، إشارة جاري الإرسال/فشل، وإظهار الردود الصادرة في السلسلة. |
| الرابعة: سياق العملاء والتسويق | جلب ملف العميل عندما تسمح صلاحيات Meta، وربط `ad_id` و`ref` و`post_id` بجداول الحملات | بطاقة عميل، مصدر المحادثة، تقارير تحويلات حسب الحملة. |
| الخامسة: الاعتمادية والحوكمة | `MEDIUMTEXT` للحمولات الكبيرة، قيد فريد للمحادثة، صف مهام دائم بعد الإقرار، سياسة احتفاظ بالحمولات | حماية أفضل من التكرار وفقد الدفعات، وواجهة أكثر موثوقية. |

## الخلاصة

السيرفر وقاعدة البيانات **مجهزان لاستقبال الحمولات الأساسية** وإنشاء صندوق بريد أولي آمن، ولا سيما النصوص والتعليقات الجديدة. لكنهما ليسا مجهزين بعد لاستغلال **كل** ما ترسله Meta في واجهة ثرية: أغلب البيانات الإضافية آمنة في الحمولة الخام لكنها غير مطبعة أو معروضة. البدء بالمرحلتين الأولى والثانية سيجعل صندوق البريد يعرض الوسائط، سياق المنشور، الردود، الحذف والتعديل، والتفاعلات بصورة متوافقة مع واقع رسائل وتعليقات Meta.
