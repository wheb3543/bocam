# خطة المرحلة 4: الترخيص وحماية التشغيل

**الحالة:** مكتملة بعد التنفيذ والمراجعة
**التاريخ:** 2026-09-11  
**المرحلة الرئيسية:** 4 من 19  
**المنهجية:** Phase-Gate Methodology  
**نطاق المرحلة:** التحقق المحلي من الترخيص، Hardware ID، التوقيع، النطاق، الانتهاء، الميزات، heartbeat، kill switch، والطلبات المركزية

## 1. هدف المرحلة

إنتاج توثيق تقني وقانوني منضبط لنظام الترخيص وحماية التشغيل، مطابق للسلوك الفعلي للكود، ويفصل بوضوح بين:

- ما يفعله النظام حاليًا.
- ما هو حماية واجهة أو Feature Gate.
- ما هو تحقق خادمي أو محلي.
- ما هو مقصود لكنه غير مثبت أو مؤجل.
- ما يحتاج قرارًا قانونيًا أو أمنيًا قبل اعتماده.

لا تهدف هذه المرحلة إلى تقوية الحماية أو تغيير Kill Switch أو تعديل خوارزمية التوقيع. أي تغيير سلوكي أمني يحتاج موافقة مستقلة بعد توثيق الفجوة.

### 2.2 النتائج المثبتة

| الرمز | النتيجة | الأثر التوثيقي |
|---|---|---|
| F4-01 | التحقق المحلي يستخدم توقيع RSA-PSS مع SHA-256 ومفاتيح عامة حالية/سابقة | يجب توثيق خوارزمية التحقق ومكان المفتاح العام دون كشف الخاص |
| F4-02 | Hardware ID يعتمد MAC لواجهة شبكة، مع قيم configured/license fallback في بعض الحالات | يجب توثيق مصادر البصمة وحدود ثباتها دون وعد بتفرد مطلق |
| F4-03 | التحقق يشمل hardware ID والانتهاء والميزات والنطاق عند ضبط `LICENSE_DOMAIN` أو روابط النشر | يجب فصل شروط التحقق الإلزامية عن الشروط المشروطة بالبيئة |
| F4-04 | `initializeLicense(true)` يسمح ببدء الخادم عند غياب ملف الترخيص ووضعه في activation mode | يتعارض مع ادعاءات بعض الوثائق عن الإيقاف الفوري؛ يجب تصحيح الوثائق لا تخمين السلوك |
| F4-05 | `validateLicense` يعيد `LicenseInfo` غير صالح عند فشل أغلب الحالات بدل إنهاء العملية مباشرة | يجب وسم Kill Switch الحالي كحالة تحتاج تحققًا، وعدم وصفه كإيقاف مؤكد |
| F4-06 | `featureMiddleware` يحمي إجراءات tRPC بالميزات، و`ProtectedRoute` يحمي الواجهة، مع مسار admin bypass منفصل | يجب توثيق الفرق وخطر bypass وحدوده |
| F4-07 | `licenseRouter` يعرض معلومات وHardware ID وfeature checks عبر إجراءات عامة، وبعض طلبات التفعيل المركزية عامة قبل تسجيل الدخول | يجب توثيق سبب الإتاحة العامة والبيانات التي يجب ألا تظهر |
| F4-08 | heartbeat يعتمد `IDEA_HUB_URL` لبناء `/api/heartbeat/bocam`، ويفشل بصمت عند غياب الرابط أو فشل الشبكة | يجب عدم توثيق `CENTRAL_ACTIVATION_URL` كأنه مصدر heartbeat الفعلي دون تحقق |
| F4-09 | heartbeat يسجل Hardware ID ونسخة الترخيص والحالة محليًا، ويحتفظ بآخر 30 سجلًا | يجب توثيق البيانات والاحتفاظ والخصوصية |
| F4-10 | central license request يحفظ الطلبات المؤقتة بملفات `0600` ويتحقق محليًا من الترخيص قبل الدعم | يجب توثيق دورة الطلب والبيانات التشخيصية والملفات المحلية |
| F4-11 | تثبيت الترخيص المركزي يكتب ملفًا مؤقتًا ثم يستبدله ويعيد التحقق ويحذف الملف عند الفشل | يجب توثيق atomic replacement والتحقق بعد التثبيت |
| F4-12 | وثائق الترخيص الحالية تدعي أعداد صفحات وKill Switch وتشغيلًا قد لا يطابق التنفيذ الحالي | يجب فصل القانوني عن التقني وتصحيح الادعاءات غير المثبتة |
| F4-13 | اختبارات الترخيص تغطي validation وrotation وfeature middleware وcentral requests، لكن لا تثبت كل دورة production | يجب تحديد حدود الاختبارات في المرجع |

### 2.3 الفرضية التشغيلية

إذا أُعيد بناء وثائق الترخيص من `validation.ts` و`helpers.ts` و`license.ts` و`heartbeat.ts` والاختبارات، فستصبح الحدود بين التحقق المحلي، التفعيل المركزي، Feature Gates، والتشغيل غير المرخص واضحة، ويمكن رفع أي فجوة أمنية كقرار منفصل دون ادعاء حماية غير موجودة.

**التحقق المضاد:** أي ادعاء مثل "Kill Switch يوقف الخادم دائمًا" أو "التشغيل يعمل دون اتصال في كل الحالات" لا يُعتمد إلا إذا دعمه مسار كود واختبار واضح.

## 3. نطاق المرحلة وحدودها

### داخل النطاق

- دورة ملف الترخيص ومساره وبنيته العامة.
- التوقيع RSA-PSS/SHA-256 والمفتاح العام.
- Hardware ID والنطاق والانتهاء والميزات.
- initialize/validate/license status وactivation mode.
- Feature Middleware وFeatureGate وProtectedRoute.
- heartbeat وAnti-Clock-Tampering وسجلاته المحلية.
- طلبات التفعيل والميزات والدعم المركزية.
- تحديث `docs/licensing/` و`SECURITY.md` ومصفوفة التغطية وسجل التعارضات.
- فصل التوثيق القانوني عن التوثيق التقني وتوسيم الادعاءات غير المثبتة.

### خارج النطاق

- تغيير خوارزمية RSA أو طريقة Hardware ID.
- تفعيل Kill Switch فعلي أو إزالة مسار activation mode.
- تغيير صلاحيات license router أو إخفاء Hardware ID دون موافقة أمنية مستقلة.
- تعديل heartbeat أو endpoints المركزية أو سياسات الاحتفاظ.
- إصدار رأي قانوني نهائي حول MIT/Proprietary/HIPAA/GDPR.
- إدخال مفاتيح خاصة أو تراخيص حقيقية أو Hardware IDs في الوثائق.

## 4. خطة التنفيذ الدقيقة

### المهمة 4.1: توثيق نموذج الترخيص وملفاته

**الإجراء:** وصف ملف الترخيص وحقوله العامة ومساره حسب `LICENSE_PATH` و`TENANT_ROOT` و`TENANT_ID`، مع منع عرض المفتاح الخاص.  
**الناتج:** مرجع بنية الترخيص ومسار القراءة والتثبيت.  
**معيار القبول:** كل حقل موثق مرتبط بـtype أو parser فعلي.

### المهمة 4.2: توثيق التوقيع والتحقق

**الإجراء:** شرح Base64 license envelope وRSA-PSS وSHA-256 وتعدد المفاتيح العامة والتحقق بعد التثبيت.  
**الناتج:** مخطط تحقق تقني.  
**معيار القبول:** لا تستخدم الوثيقة كلمة encryption عندما يكون التنفيذ توقيعًا رقميًا فقط.

### المهمة 4.3: توثيق Hardware ID والنطاق والانتهاء

**الإجراء:** توثيق MAC detection وconfigured/file fallback و`LICENSE_DOMAIN` و`BOCAM_PUBLIC_URL` و`SERVER_URL` وتاريخ الانتهاء.  
**الناتج:** جدول شروط التحقق والبيئات المؤثرة.  
**معيار القبول:** توضيح حدود تغير MAC أو استخدام fallback وعدم ادعاء ثبات مطلق.

### المهمة 4.4: توثيق activation mode وKill Switch الفعلي

**الإجراء:** مطابقة ادعاءات الإيقاف مع `initializeLicense(true)` و`validateLicense` وstartup flow، وتصنيف Kill Switch إلى implemented/partial/not verified حسب الدليل.  
**الناتج:** تصحيح مرجع التشغيل غير المرخص.  
**معيار القبول:** لا توصف آلية غير مثبتة بأنها توقف الخادم دائمًا.

### المهمة 4.5: توثيق Feature Gates

**الإجراء:** فصل `requireFeature` و`requireFeatureWithAdminBypass` و`FeatureGate` و`useLicense` عن RBAC، وتوثيق loading وFORBIDDEN وadmin bypass.  
**الناتج:** مرجع حماية الميزات على API والواجهة.  
**معيار القبول:** لا يعتمد أمن API على إخفاء الواجهة فقط.

### المهمة 4.6: توثيق heartbeat وAnti-Clock-Tampering

**الإجراء:** توثيق مصدر الرابط، البيانات المرسلة، timeout، الفشل الصامت، ملفات `.last-successful-run` و`.heartbeat-log`، وسياسة الاحتفاظ.  
**الناتج:** runbook تقني محدود للـ heartbeat.  
**معيار القبول:** تضمين مخاطر Hardware ID والبيانات التشغيلية وعدم وصف heartbeat كإيقاف عند الفشل إذا كان الكود يفشل بصمت.

### المهمة 4.7: توثيق الطلبات المركزية والدعم

**الإجراء:** شرح طلب الترخيص وتفعيل الميزة والدعم، الملفات المؤقتة، انتهاء الطلب، fingerprints، diagnostics، والمرفقات.  
**الناتج:** دورة طلب مركزية مع ضوابط البيانات.  
**معيار القبول:** لا تظهر مفاتيح الترخيص أو الأسرار في المتصفح أو الوثائق.

### المهمة 4.8: مطابقة اختبارات الترخيص

**الإجراء:** ربط validation وrotation وprovided license وfeature middleware وcentral requests وrouter tests بالادعاءات الموثقة.  
**الناتج:** جدول behavior → test → documentation.  
**معيار القبول:** توضيح ما لا تغطيه الاختبارات، خصوصًا startup production وheartbeat الحقيقي.

### المهمة 4.9: فصل القانوني عن التقني

**الإجراء:** تحديث `LICENSE_GUIDE.md` ليقسم الترخيص القانوني عن المرجع التقني، وإزالة أو وسم أعداد الصفحات والادعاءات غير المثبتة.  
**الناتج:** وثيقة قانونية لا تتظاهر بأنها إثبات تنفيذي، ومرجع تقني قابل للتدقيق.  
**معيار القبول:** أي نص قانوني غير معتمد يوسم بأنه إرشادي ويحتاج مراجعة مالك المشروع/المستشار.

### المهمة 4.10: تحديث الأمان والمصفوفة والتعارضات

**الإجراء:** ربط ملفات الترخيص والاختبارات ووثائقها، وتسجيل التعارضات مثل Kill Switch وCENTRAL_ACTIVATION_URL وpublic license procedures.  
**الناتج:** traceability وقرارات مؤجلة واضحة.  
**معيار القبول:** كل فجوة لها رمز وحالة ومالك.

### المهمة 4.11: التحقق وإغلاق المرحلة

**الإجراء:** تشغيل اختبارات الترخيص وfeature middleware وcentral requests، ثم `pnpm check` و`pnpm docs:check` وPrettier وفحص الروابط، وإعداد تقرير الإغلاق.  
**الناتج:** تقرير نتائج وبوابة المرحلة 5.  
**معيار القبول:** اجتياز القائمة وتوثيق أي اختبار يعتمد على ملفات أو بيئة غير متاحة.

## 5. معايير الجودة

- عدم نشر private keys أو license keys أو Hardware IDs الحقيقية.
- التفريق بين signing وencryption وبين validation وactivation.
- التفريق بين local offline validation وcentral heartbeat/request flows.
- كل ادعاء Kill Switch أو anti-tampering مرتبط بمصدر واختبار أو موسوم كغير مثبت.
- توثيق بيانات heartbeat والدعم وفق مبدأ تقليل البيانات.
- عدم اعتبار Feature Gate حماية تفويض كاملة.
- عدم تغيير آلية الحماية أثناء تحديث الوثائق.
- فصل النص القانوني عن الادعاء التقني وعن دليل التشغيل.
