# خطة المرحلة 5: قاعدة البيانات والترحيلات

**الحالة:** مكتملة بعد التنفيذ والمراجعة
**التاريخ:** 2026-09-12
**المرحلة الرئيسية:** 5 من 19
**المنهجية:** Phase-Gate Methodology
**النطاق:** Drizzle schema والعلاقات والترحيلات وطبقة database ومقارنة المخطط والتوثيق المرتبط

## 1. هدف المرحلة

إنتاج مرجع قاعدة بيانات مطابق للمخطط الحالي وسجل ترحيلات قابل للتدقيق، مع فصل الحالة الحالية عن التاريخ، وربط الجداول بالمجالات والاختبارات دون تعديل schema أو migrations ضمن مشروع التوثيق.

## 2. نتائج الفحص الأولي

- يحتوي `drizzle/schema.ts` على 106 تعريفات `mysqlTable` وفق نمط المصدر الحالي.
- يحتوي مجلد `drizzle/` على 110 ملفات SQL في الجذر.
- توجد تعريفات علاقات صريحة في `drizzle/relations.ts`، بينما توجد قيود foreign key داخل `schema.ts` أيضًا.
- `docs/architecture/DATABASE_SCHEMA.md` و`drizzle/MIGRATIONS_GUIDE.md` كانا يحملان أرقامًا أقدم؛ صُحح خط الأساس ووُسمت الحاجة إلى تحديث تدريجي.
- `scripts/compare_schema.cjs` يحتاج اتصال MySQL/TiDB فعليًا ولا يمكن اعتباره فحصًا منفذًا دون بيئة قاعدة بيانات.
- بعد تشغيل قاعدة البيانات، تم الاتصال عبر `DATABASE_URL`: تطابقت جميع جداول وأعمدة التطبيق، والجدول الإضافي الوحيد هو `__drizzle_migrations` الإداري.

## 3. حدود المرحلة

### داخل النطاق

- جرد الجداول والأعمدة والأنواع والقيم الافتراضية والفهارس والقيود.
- مطابقة `schema.ts` مع `relations.ts` وSQL و`meta/_journal.json`.
- تصنيف الترحيلات الفعلية وplaceholder دون التخمين من الاسم.
- ربط الجداول بخدمات وراوترات المجالات والاختبارات.
- تحديث مرجع schema وERD ودليل migrations ومصفوفة التغطية وسجل التعارضات.

### خارج النطاق

- تعديل schema أو migration SQL أو بيانات قاعدة تشغيلية.
- إعادة تصميم العلاقات أو سياسات الاحتفاظ والحذف.
- تشغيل مقارنة إنتاجية دون اعتماد بيئة واتصال آمن.
- حذف أو إعادة تسمية ملفات الترحيل.

## 4. خطة التنفيذ

### المهمة 5.1: جرد schema

استخراج أسماء الجداول والأعمدة والأنواع والقيود والفهارس من المصدر، وتسجيل أي نمط لا يلتقطه parser الحالي.

### المهمة 5.2: خريطة العلاقات

مطابقة `references` في `schema.ts` مع `relations.ts` وERD، وتسجيل علاقات schema التي لا تملك تعريف Drizzle صريحًا.

### المهمة 5.3: سجل الترحيلات

قراءة SQL و`meta/_journal.json` وتصنيف الترحيلات حسب أثرها الفعلي، مع إبقاء الأسماء والتسلسل كما هو.

### المهمة 5.4: ربط طبقة البيانات

ربط مجموعات الجداول بوحدات `server/database/` والراوترات والخدمات والاختبارات، وتحديد الجداول غير المستخدمة أو غير الموثقة.

### المهمة 5.5: مطابقة تشغيلية اختيارية

تشغيل `scripts/compare_schema.cjs` فقط عند توفير قاعدة اختبار واتصال معتمد، وتسجيل حدود parser ونتائج المقارنة دون بيانات إنتاج.

**النتيجة الحالية:** تم الاتصال الحي بنجاح عبر MySQL driver الموجود في المشروع. بعد إصلاح parser لاستخراج AST واستخدام `DATABASE_URL`، أعادت المقارنة: `missingTables=[]` و`mismatchedTableCount=0`، مع `__drizzle_migrations` كجدول إداري خارج schema.

### المهمة 5.6: تحديث الوثائق

تحديث المرجع الحالي وERD ودليل الترحيلات تدريجيًا، مع فصل المرجع canonical عن التقارير التاريخية.

### المهمة 5.7: التحقق والإغلاق

تشغيل schema/migration checks و`pnpm docs:check` و`pnpm check` وفحوص الروابط، ثم إعداد تقرير إغلاق قبل طلب الانتقال إلى المرحلة 6.
