## 2. النتائج المثبتة بالكود والاختبارات

- **حصر الاختبارات الحالي:** يحتوي المشروع على **196 ملف اختبار** مقسمة كالآتي:
  - **97 ملف اختبار خادم (`server/`):** تغطي راوترات tRPC، قواعد البيانات، الصلاحيات RBAC، Webhooks، والتكاملات.
  - **93 ملف اختبار واجهة (`client/`):** تغطي المكونات المشتركة، الإطار الإداري والتبويبات، الوضع الداكن، الفلاتر والجداول، والخطافات.
  - **6 ملفات اختبار E2E (`e2e/`):** تغطي إمكانية الوصول بمحرك `@axe-core/playwright`، ولوحة التحكم، والمصادقة، والصفحات العامة، وبوابة المريض، وWhatsApp.
- **بيئة العزل والمحاكاة (`vitest.setup.ts`):** توفير بيئة اختبار آمنة تحاكي `localStorage`, `sessionStorage`, `window.matchMedia`, وبروتوكول البث اللحظي `EventSource` دون الاعتماد على خوادم حية أو كشف أسرار.
- **بوابات الجودة في CI (`.github/workflows/ci.yml`):**
  - فحص الصياغة والأنماط (Lint) والتنسيق (Prettier).
  - فحص الأنواع الصارم عبر `tsc --noEmit` بمحصلة 0 أخطاء.
  - فحص خط أساس التغطية عبر `pnpm coverage:check` مع حظر أي تراجع.
  - فحوصات السلامة الإضافية: `pnpm exports:check`, `pnpm schema:migrations:check`, `pnpm quality:check`.

## 3. الحدود المعمارية وما لا تثبته الاختبارات

1. **المحاكاة للخدمات الخارجية:** تحاكي الاختبارات واجهات Meta وWhatsApp وS3. نجاح الاختبار يثبت سلامة المنطق الداخلي والتفاعل مع الردود، لكنه لا يثبت صحة بيانات الاعتماد أو اتصال الشبكة في البيئة الإنتاجية الحية.
2. **عزل قاعدة البيانات أثناء اختبارات الوحدة:** لا تتصل اختبارات الوحدة بقاعدة بيانات MySQL الحقيقية؛ بل تفحص مطابقة الترحيلات بشكل مستقل عبر سكربتات فحص الـ Schema.
3. **متطلبات تشغيل خادم التطوير والإنتاج:** تعتمد الاختبارات على متغيرات افتراضية في `vitest.setup.ts`. يتطلب تشغيل خادم الإنتاج توفير ملف `.env` صالح يطابق الدليل المرجعي لمتغيرات البيئة.
