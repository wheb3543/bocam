# خطة المرحلة 1: تعريف النظام والحدود

**الحالة:** مكتملة بعد التنفيذ والمراجعة  
**التاريخ:** 2026-09-11  
**المرحلة الرئيسية:** 1 من 19  
**المنهجية:** Phase-Gate Methodology  
**نطاق المرحلة:** الوصف العام للنظام، حدود الطبقات، التوجيه، المصطلحات، ومسارات المستخدمين

## 1. هدف المرحلة

إنتاج وصف دقيق ومختصر للنظام الحالي كما يعمل في الكود، يوضح ما هو BOCAM CRM، من يستخدمه، كيف تدخل الطلبات إلى النظام، ما حدود الواجهة والخادم والبيانات والتكاملات، وما الميزات الموجودة فعليًا دون ادعاءات قديمة أو ميزات مخطط لها.

لا تشمل هذه المرحلة إعادة توثيق تفاصيل المجالات مثل WhatsApp أو CMS أو الصلاحيات. ستسجل روابطها وحدودها فقط، وتترك تفاصيلها للمراحل المتخصصة.

### 2.3 الفرضية التشغيلية

إذا أُعيد بناء تعريف النظام من نقاط الدخول والتوجيه وتجميع الراوتر وإقلاع الخادم، ثم قورنت كل ميزة معلنة بمصدر فعلي، فسيصبح `README.md` ومرجع المعمارية صالحين كنقطة دخول دون تكرار تفاصيل المجالات.

**التحقق المضاد:** أي ميزة أو عدد لا يمكن ربطه بملف أو اختبار أو مصدر واضح سيُوسم `needs-verification` أو يُنقل إلى قسم المخطط، ولن يُعرض كحقيقة حالية.

## 3. نطاق المرحلة وحدودها

### داخل النطاق

- تعريف هوية النظام والاسم المعتمد.
- وصف الجمهور والواجهات الرئيسية.
- خريطة نقاط الدخول والمسارات العامة والإدارية وبوابة المريض.
- خريطة تدفق طلبات الواجهة إلى الخادم والبيانات والتكاملات.
- تعريف حدود `client` و`server` و`shared` و`drizzle` و`e2e` و`deploy`.
- قاموس المصطلحات الأساسية.
- مطابقة الميزات العامة المعلنة مع مصادرها.
- تحديث `README.md` و`docs/architecture/ARCHITECTURE.md` والروابط المركزية عند الحاجة.

### خارج النطاق

- توثيق تفاصيل API أو schema أو الصلاحيات أو WhatsApp أو CMS.
- تعديل بنية التطبيق أو التوجيه أو الراوترات.
- إصلاح التكرار البرمجي في `AdminContentRoutes.tsx`.
- تغيير اسم المنتج أو السياسة القانونية دون قرار صاحب المشروع.
- توثيق سلوك غير موجود حاليًا لمجرد وروده في وثيقة قديمة.

## 4. خطة التنفيذ الدقيقة

### المهمة 1.1: تثبيت الهوية والمصطلحات

**الإجراء:** مقارنة أسماء BOCAM وSGH CRM Portal والاسم التجاري والوصف الطبي، وتسجيل الاسم المعتمد ومرادفاته وسياقات استخدامها.  
**الناتج:** قرار مصطلحات داخل الوثيقة ومرجع موحد للاسم.  
**معيار القبول:** لا توجد عناوين متعارضة في الوثائق التي تُحدّث، وأي اسم تاريخي موسوم بوضوح.

### المهمة 1.2: حصر نقاط الدخول

**الإجراء:** توثيق تشغيل العميل والخادم ومسار build/start، وبوابة الترخيص، ونقطة `/api/trpc`، والمسارات العامة للتكاملات.  
**الناتج:** مخطط نقاط دخول مع مصادر الملفات.  
**معيار القبول:** كل نقطة دخول موثقة مرتبطة بملف فعلي أو تسجل كفجوة.

### المهمة 1.3: حصر واجهات المستخدم

**الإجراء:** استخراج المسارات من `App.tsx` و`AdminContentRoutes.tsx` وتصنيفها إلى public/admin/patient/system، دون نسخ مكونات كل صفحة.  
**الناتج:** جدول مسارات قابل للقراءة وروابط للمرحلة المختصة.  
**معيار القبول:** لا توجد مسارات موثقة غير موجودة، وتظهر حواجز الترخيص والميزات حيث تؤثر على الوصول.

### المهمة 1.4: توثيق حدود الإدارة

**الإجراء:** وصف `/admin/*` باعتباره shell إداريًا يحتوي مجالات إدارة المحتوى، الحجوزات، الحملات، WhatsApp، الاتصالات، التقارير، الفرق، النظام، والمستخدمين.  
**الناتج:** خريطة إدارية عالية المستوى.  
**معيار القبول:** كل مجموعة صفحات مرتبطة بمرحلة مجال، ولا تُعرض تفاصيل صلاحيات قبل مرحلة RBAC.

### المهمة 1.5: توثيق بوابة المريض

**الإجراء:** وصف layout ومسارات login/home/appointments/offers/camps/results/profile وتدفقها العام.  
**الناتج:** خريطة رحلة واجهة المريض دون تفاصيل البيانات الطبية.  
**معيار القبول:** تمييز المسارات العامة عن مسارات المريض المحمية، مع إحالة مرحلة المرضى.

### المهمة 1.6: توثيق حدود الخادم

**الإجراء:** استخراج طبقات الإقلاع من `server/_core/index.ts`: middleware، OAuth، REST routes، webhooks، scheduled routes، SSE، health، Swagger، tRPC، static/Vite.  
**الناتج:** مخطط تدفق الخادم وملخص مسؤولية كل طبقة.  
**معيار القبول:** لا يوصف النظام بأنه tRPC فقط، ولا تخلط webhooks العامة بإجراءات tRPC.

### المهمة 1.7: توثيق حدود البيانات والتكاملات

**الإجراء:** ربط `drizzle/` و`server/database/` و`shared/` بمخطط الطبقات، ووضع التكاملات الخارجية في طبقة مستقلة.  
**الناتج:** خريطة عالية المستوى للبيانات والتكاملات.  
**معيار القبول:** لا تُنسب مسؤولية تخزين أو تكامل إلى طبقة لا تنفذه فعليًا.

### المهمة 1.8: مطابقة الميزات المعلنة

**الإجراء:** مراجعة كل ميزة رئيسية في `README.md` و`docs/architecture/ARCHITECTURE.md` وربطها بصفحة أو router أو service أو اختبار.  
**الناتج:** جدول current/needs-verification/planned/unsupported.  
**معيار القبول:** كل ادعاء رئيسي له دليل أو وسم واضح، وتُزال الأعداد غير القابلة للصيانة أو تُربط بمصدر.

### المهمة 1.9: بناء قاموس المصطلحات

**الإجراء:** تعريف CRM، CMS، Lead، Patient، Appointment، Campaign، Social Inbox، Social Publishing، Integration، Router، Service، Job، Webhook، PWA.  
**الناتج:** قاموس مصطلحات ثنائي اللغة عند الحاجة.  
**معيار القبول:** لا يستخدم المصطلح بمعانٍ متناقضة بين README والمعمارية والفهرس.

### المهمة 1.10: تحديث تعريف النظام والمعمارية

**الإجراء:** تحديث `README.md` ووثيقة المعمارية اعتمادًا على نتائج المطابقة، مع إبقاء التفاصيل المتخصصة في وثائق مراحلها.  
**الناتج:** وثيقتان مرجعيتان متوافقتان مع الخريطة الحالية.  
**معيار القبول:** الروابط صحيحة، والأوصاف قابلة للتتبع إلى الكود، ولا توجد تعليمات قديمة في الأقسام المعدلة.

### المهمة 1.11: ربط الخريطة بالمصفوفة

**الإجراء:** تحديث `DOCUMENTATION_COVERAGE_MATRIX.md` بمسارات النظام والواجهات والمصادر التي تم التحقق منها.  
**الناتج:** تغطية أفضل للطبقة العامة مع إحالات للمراحل اللاحقة.  
**معيار القبول:** كل مسار رئيسي في الخريطة له صف في المصفوفة أو استثناء مسجل.

### المهمة 1.12: التحقق وإغلاق المرحلة

**الإجراء:** تشغيل فحص الروابط والسجل والتنسيق، ومقارنة diff مع هذه الخطة، ثم إعداد تقرير إغلاق المرحلة.  
**الناتج:** تقرير إغلاق ومصفوفة فجوات محدثة.  
**معيار القبول:** اجتياز قائمة القبول وتسجيل كل قرار مؤجل قبل طلب المرحلة 2.

## 5. معايير الجودة

- الوصف العام يشرح النظام دون نسخ كود أو قوائم procedures كاملة.
- كل رسم أو جدول يملك مصدرًا فعليًا.
- لا توجد أرقام ثابتة إلا إذا كان مصدرها قابلًا للتوليد أو موضحًا بتاريخ.
- كل ميزة مصنفة إلى حالية أو قيد التحقق أو مخططة أو غير مدعومة.
- فصل وصف المنتج عن بنية التنفيذ وعن دليل التشغيل.
- عدم تعديل الكود أو تغيير التوجيه.
- الحفاظ على أسماء المسارات الفعلية كما هي.
- أمثلة Mermaid أو النصوص المعمارية لا تدعي بروتوكولًا غير موجود.
- الروابط المحلية تمر بفحص السجل وفحص الروابط.
- اللغة واضحة، والمصطلحات الإنجليزية للكود لا تُترجم بطريقة تكسر البحث.
